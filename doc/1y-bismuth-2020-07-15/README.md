# Bismuth（2020/7/15 版）の非停止

## Bismuth

Bismuth は Syst3ms による Y 数列に似た表記です（[User blog:Syst3ms/Bismuth : not Y sequence, but close](https://googology.fandom.com/wiki/User_blog:Syst3ms/Bismuth_:_not_Y_sequence,_but_close)）。ブログ記事には展開の手順の説明がなく、定義は Kotlin のプログラム [Syst3ms/Bismuth](https://github.com/Syst3ms/Bismuth) そのものです。

ここで扱うのは、リポジトリの最新のコミット [`bf7ba654`](https://github.com/Syst3ms/Bismuth/blob/bf7ba654/src/io/github/syst3ms/bismuth/Bismuth.kt)（2020-07-14 21:25 UTC、日本時間では 2020-07-15、"Fix diagonal finding&expansion method"）の版です。2019/9/29 版については [1y-bismuth](../1y-bismuth/README.md) にあります。

数列 $`X`$ をブラケット $`n`$ で展開した結果を $`X[n]`$ と書きます。プログラムは $`(\ldots)[0]`$ も受け付けるので、ブラケットは $`n \ge 0`$ です。整数は上限のない整数として扱います（Bismuth を数学の表記として読みます）。

## 結果

$`X = (1,4,12,9,12,20)`$ とします。次を Lean で証明しました（[Main.lean](../../lean/1y-bismuth-2020-07-15/Main.lean) の `Bismuth2020.main_theorem`）。

1. $`X`$ は標準形である。つまり $`(1,5)`$ から展開を 58 回繰り返して得られる。使うブラケットは 0 と 1 である。
2. $`0 \le n \le 20`$ のどの $`n`$ についても、プログラムに $`X[n]`$ を入力すると計算が終わらない。

$`n \gt 20`$ は証明していません。

## 展開の手順

プログラムから読み取った展開の手順のうち、この例で使う部分を書きます。位置と行は 0 から数えます。プログラムは $`X[n]`$ を、コピーの回数 $`t = n + 1`$ で計算します。以下の手順はコピーの回数 $`t`$ で書きます。

### 山

数列 $`X = (X_0, \dots, X_{L-1})`$ から、行 $`V_0, V_1, \dots, V_R`$（どれも長さ $`L`$）と、行ごとの親までの距離 $`O_0, \dots, O_R`$ を作ります。この 2 つの表をそれぞれ山、距離の表と呼びます。

- $`V_0 = X`$。
- 行 $`r`$ での位置 $`i`$ の親 $`P`$ は、次の探索で決めます。
  - 探索を始める位置 $`j`$ は、$`r = 0`$ なら $`i - 1`$、$`r \ge 1`$ なら $`i - \max(O_{r-1}(i), 0)`$ です。
  - $`j \ge 0`$ の間、次を繰り返します。$`1 \le V_r(j) \lt V_r(i)`$ なら $`P = j`$ として終わります。$`V_r(j) = 0`$ なら親はありません。どちらでもなければ $`j`$ を $`\max(O_r(j), 1)`$ だけ左に動かします（まだ決まっていない距離は 0 とみなします）。
- $`V_{r+1}(i) = V_r(i) - V_r(P)`$。親がなければ $`V_{r+1}(i) = 0`$。
- 距離は、親があれば $`O_r(i) = i - P`$ です。親がなければ、$`V_r(i) = 0`$ か $`V_r(0), \dots, V_r(i-1)`$ がすべて 0 のとき $`O_r(i) = 0`$、それ以外は $`O_r(i) = -V_r(i)`$ です。
- 最後の位置 $`L - 1`$ が一番上の行で親を持つ間、行を足していきます（この判定の細部は省略します）。
- **一番上の行の距離 $`O_R`$ は計算されず、すべて 0 のままです。**

### 2 つの場合

$`X`$ の展開は、山の右下の値 $`V_R(L-1)`$ で 2 つに分かれます。

- $`V_R(L-1) \le 1`$ のとき（通常の展開）: 悪い根 $`b = (L-1) - O_{R-1}(L-1)`$ から位置 $`L-2`$ までの部分を $`t`$ 回並べた数列を作ります。この途中で、距離の表を複写手順（次の節）で広げます。並べるときの値の決め方は、この例で止まらなくなることには関係しないので省略します。
- $`V_R(L-1) \ge 2`$ のとき: 経路を使う展開（その次の節）をします。

### 複写手順

$`h`$ 行 $`w`$ 列の表 $`M`$（行 $`M_0, \dots, M_{h-1}`$）を、位置 $`b`$ とコピーの回数 $`t`$ で広げる手順です。

1. $`c = w - 1 - b`$ とする。$`c`$ は $`b`$ より右にある列の数です。幅を $`W = b + c\,t + 1`$ とする。
2. 各行の右に 0 を足して $`W`$ 列にする。
3. 先頭の行の最後の項 $`M_0(W-1)`$ が 0 である間、$`k = 1, 2, 3, \dots`$ の順に次を繰り返す。
   - $`j = 0, 1, \dots, c-1`$ の順に、写し先 $`q = b + k c + j + 1`$ を決める。$`q \ge W`$ ならこの回はここで終わる。そうでなければ、各行で列 $`b + j + 1`$ の値 $`v`$ を列 $`q`$ に写す。ただし $`v \gt j + 1`$ のときは $`v + k c`$ を写す。

### 経路を使う展開

$`V_R(L-1) \ge 2`$ のとき、展開は次のように計算します。

1. 各位置 $`x`$ について、$`V_y(x) \gt 0`$ となる一番上の行 $`y(x)`$ を求めます。点 $`(x, y(x))`$ を左から並べたものを経路と呼び、経路上の値を並べた数列を $`D = (V_{y(0)}(0), \dots, V_{y(L-1)}(L-1))`$ とします。
2. 各位置 $`x`$ について、山と距離の表から $`D`$ の行 0 の距離 $`F(x)`$ を決めます。求め方はこの例で止まらなくなることに直接関係しないので省略し、値だけ示します。
3. $`D`$ をコピーの回数 $`t + 1`$ で展開します。このとき、$`D`$ の山の行 0 の距離には $`F`$ を使います。$`D`$ の悪い根を $`b_D`$ とします。
4. 経路の位置 $`b_D`$ の点 $`(b_D, y(b_D))`$ を取ります。距離の表の行 $`y(b_D)`$ の、位置 $`b_D`$ から右端までを切り出します。これを悪い部分と呼びます。
5. 悪い部分（1 行の表）を、位置 0、コピーの回数 $`t`$ で複写手順により広げます。
6. その後、新しい表を組み立てます。この例はこの前の手順 5 で止まらなくなるので、ここからは省略します。

## X[n] が止まらない理由

### X の山

```
位置   0  1  2  3  4  5
V_0    1  4 12  9 12 20
V_1    0  3  8  5  3  8
V_2    0  0  5  2  0  5

O_0    0  1  1  2  1  1
O_1    0  0  1  2 -3  1
O_2    0  0  0  0  0  0
```

$`R = 2`$ で、右下の値は $`V_2(5) = 5 \ge 2`$ なので、経路を使う展開です。一番上の行の距離 $`O_2`$ は計算されないので、すべて 0 です。

### 経路と D

```
位置          0  1  2  3  4  5
y(x)          0  1  2  2  1  2
D             1  3  5  2  3  5
F             0  1  1  3  4  1
```

### D の展開

$`D = (1,3,5,2,3,5)`$ を、行 0 の距離に $`F`$ を使ってコピーの回数 $`t + 1`$ で展開します。$`D`$ の山は次のとおりです。

```
位置   0  1  2  3  4  5
V_0    1  3  5  2  3  5
V_1    0  2  2  1  2  2
V_2    0  0  0  0  0  1

O_0    0  1  1  3  4  1
O_1    0  0 -2 -1 -2  2
O_2    0  0  0  0  0  0
```

右下の値は $`V_2(5) = 1`$ なので通常の展開で、悪い根は $`b_D = 5 - O_1(5) = 3`$ です。この展開は終わります。

### 悪い部分

経路の位置 3 の点は $`(3, y(3)) = (3, 2)`$ です。距離の表の行 2 の位置 3〜5 を切り出すと、悪い部分は

```math
(O_2(3), O_2(4), O_2(5)) = (0, 0, 0)
```

です。行 2 は一番上の行なので、距離は計算されず 0 のままになっています。

### 複写手順が終わらない

悪い部分 $`(0,0,0)`$ を、位置 $`b = 0`$、コピーの回数 $`t = n+1`$ で広げます。$`w = 3`$ なので $`c = 2`$、幅は $`W = 2(n+1) + 1 = 2n + 3`$ です。写す値はどれも 0 なので、写しても 0 のままです。$`n = 2`$（$`W = 7`$）なら、表（1 行）は次のようになります。

```
始め    0 0 0 0 0 0 0   最後の項が 0 なので続ける
1 回目  0 0 0 0 0 0 0   列 1, 2 の (0, 0) を列 3, 4 に写す。最後の項が 0 なので続ける
2 回目  0 0 0 0 0 0 0   列 1, 2 の (0, 0) を列 5, 6 に写す。最後の項が 0 なので続ける
3 回目  0 0 0 0 0 0 0   写し先 7 が幅 7 以上なので何も写さない。最後の項が 0 なので続ける
4 回目  0 0 0 0 0 0 0   同じ
…
```

表は何回繰り返しても変わらず、最後の項は 0 のままなので、繰り返しは終わりません。したがって $`X[n]`$ の計算は終わりません。$`n`$ によって変わるのは幅 $`W = 2n + 3`$ だけです。

2019/9/29 版の例（[1y-bismuth](../1y-bismuth/README.md)）では、写す列が 0 個でした。こちらでは写す列が 2 個ありますが、写す値がすべて 0 です。

## 形式化の方法

### プログラムの書き直し（[Model.lean](../../lean/1y-bismuth-2020-07-15/Model.lean)）

`Bismuth.kt` を関数ごとに Lean に書き直しました。配列の読み書きや表の大きさの変更など、2019/9/29 版と Kotlin のコードが同じ部分は、2019/9/29 版の書き直し（[1y-bismuth の Model.lean](../../lean/1y-bismuth/Model.lean)）を使っています。

Lean の関数は必ず終わらなければならないので、各 while ループ、各 do-while ループの反復回数と再帰の深さに上限 $`f`$ を設け、上限に達したら「上限切れ」を返すようにしています。結果は次の 4 種類です。

| 結果 | 意味 |
|---|---|
| 値 | 値を返して終わった |
| 例外 | Kotlin なら例外が出る（範囲外の添字、空の配列の最初や最後の要素など） |
| 対象外 | 書き直しが扱わない場合（親の探索で、起きないはずの上限切れ） |
| 上限切れ | 上限 $`f`$ に達した |

- 配列はリストで表し、整数は上限のない整数で表しています。
- Kotlin のプログラムは、表の大きさを変えるときに幅が変わらなければ、元の表と同じ行を使い回します。経路を使う展開で新しい表の幅が元の山と同じだと、新しい表への書き込みで元の山も書き換わり、その後の切り出しに影響します。ブラケット 0 ではいつもこの場合になります。書き直しでは、新しい表に書き込むたびに、共有されている行を元の山にも写して、この動きを再現しています。

定理の 2 は、Lean では「$`0 \le n \le 20`$ のどの $`n`$ と、どの上限 $`f`$ についても、書き直したプログラムに $`X[n]`$ を与えると上限切れになる」という形です。

### どの上限でも上限切れになることの示し方（[Decide.lean](../../lean/1y-bismuth-2020-07-15/Decide.lean)）

2019/9/29 版と同じ方法です。上限 $`f`$ を使わずに同じ計算をする関数 $`A`$ を作りました。

- $`A`$ は複写手順の中で、続ける条件 $`M_0(W-1) = 0`$ が成り立ち、しかもこの先どの回も何も写さない状態に来ると「無限ループ」と答えます。
- この先何も写さないことは、$`c \le 0`$ か、$`k`$ 回目の最初の写し先 $`b + kc + 1`$ が $`W`$ 以上であることで判定します（写し先は回ごとに右へ動くので、以後の回も写しません）。
- ほかのループには大きな固定の上限（100000 回）を使い、それを超えたら「不明」と答えます。

次の 2 つを証明しました。

1. どの入力についても、$`A`$ が「無限ループ」と答えるなら、どの上限 $`f`$ でも書き直したプログラムは上限切れになる。
2. $`0 \le n \le 20`$ について、$`X`$ と $`n`$ を与えると $`A`$ は「無限ループ」と答える。Lean のカーネルで実際に計算して確かめています（`decide +kernel`）。

$`n`$ を記号のまま扱うには、$`D`$ の通常の展開（コピーの回数 $`n+2`$）が例外を出さずに終わることを、記号のまま示す必要があり、今回は行っていません。$`n \le 100`$ を一度に計算すると、検証に使った環境のメモリ上限（8 GB）を超えました。

Lean のコードとの対応は次のとおりです。

| この文書での名前 | Lean の名前 |
|---|---|
| 書き直したプログラム | `Bismuth2020.main`（上限が引数） |
| 上限切れ / 例外 / 対象外 | `.div` / `.err` / `.unsup` |
| 関数 $`A`$ | `Bismuth2020.mainD` |
| 無限ループ / 不明 | `.stuck` / `.bound` |
| 証明 1 | `Bismuth2020.main_div_of_stuck` |
| 証明 2 | `Bismuth2020.target_stuck` |
| 標準形であること | `Bismuth2020.std_target` |
| 結果（定理全体） | `Bismuth2020.main_theorem` |

### 検証

- **公理**（[Test/Axioms.lean](../../lean/Test/Axioms.lean)）: `Bismuth2020.main_theorem` が使う公理は `propext` と `Quot.sound` だけです。`sorry`（証明の省略）と `native_decide`（コンパイルしたコードによる計算）は使っていません。
- **差分テスト**（[tools/1y-bismuth-2020-07-15/difftest.sh](../../tools/1y-bismuth-2020-07-15/difftest.sh)）: 別に書いた Python への書き直し（[bismuth.py](../../tools/1y-bismuth-2020-07-15/bismuth.py)）と Lean の書き直しに同じ入力を与え、結果を比べました。入力は次の 16366 件で、すべて一致しました。結果の内訳は、値 16272 件、例外 82 件、止まらない 12 件です。
  - $`(1,2), \dots, (1,5)`$ から展開で得られる 4000 個の数列と、ブラケット 0〜3 の組
  - 上の経路の 59 個の数列などと、ブラケット 0〜5 の組
- **元のプログラムでの確認**: 元の Kotlin プログラムは実行していません。なお、Kotlin の整数は 32 ビットなので、実際のプログラムでは、回数 $`k`$ が $`2^{30}`$ に達したところで写し先 $`q`$ の計算が範囲を超えて負になり、例外で止まると見込まれます。ここでは Bismuth を上限のない整数の表記として扱っているので、これは結論に影響しません。

```sh
git clone https://github.com/Syst3ms/Bismuth && cd Bismuth && git checkout bf7ba654
kotlinc src/io/github/syst3ms/bismuth/Bismuth.kt -include-runtime -d bismuth.jar
echo "(1,4,12,9,12,20)[1]" | timeout 60 java -jar bismuth.jar; echo exit=$?
```

## 注意

- これは「1 回の展開の計算そのものが終わらない」という非停止です。[BMS の亜種の例](../README.md)の「展開を繰り返すと無限に続く列ができる」という非停止とは種類が違います。
- 標準形であることの経路では、ブラケット 0 の展開を使っています。ブラケット 1 以上だけで $`X`$ に届くかは分かっていません。$`(1,5)`$ から降りる探索は、途中の数列が長くなりすぎて打ち切りになりました。
- Bismuth には大きな数を作る関数が定義されていないので、実際の大きな数の計算が $`X`$ を通るかは示していません。示しているのは、$`(1,5)`$ から展開で得られる数列のなかに、展開の計算が終わらないものがあることです。
